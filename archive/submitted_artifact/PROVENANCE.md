# Provenance of every table and figure

This package documents where each submitted number came from. Every copied file is byte-identical to
its source (SHA-256 of source and copy in `MANIFEST.sha256.tsv`).

New results appear in one place only: `corrected_results/`. There, pre-registered experiments replace
the parts of the evaluation that cannot stand (Tables III-VI, Fig. 2; see "Corrected experiments"
below). Nothing outside that folder was changed to alter any output. The only edit to existing data is that
`"user_id"` in the 18 IBM job-info files is replaced by `"REDACTED"`.

## Known discrepancies

**D1. The method in Sec. III is not the code that produced the numbers.** Sec. III describes an
entanglement-aware slicer that starts from the causal cone and prunes operations whose qubits have
mutual information below a threshold with the criterion. Each prune is checked by trace distance,
with a fallback for non-unitary circuits, over UED/ED/MD/CD edges. That design exists as the
June 28 prototype in `described_method/`. The code that produced Tables III-V and VII
(`rq1_rq3_rq5/qdg.py`) is simpler:
- it builds only state-carry and entanglement edges;
- it refines slices by greedy delete-and-resimulate (keep a deletion if the target fidelity stays
  >= 0.999999);
- its loader (`qasm_loader.py`, line 149 and the `SUPPORTED_GATES` filter) drops `measure`,
  `reset` and classically conditioned gates, so there are no MD or CD edges;
- the naive baseline is the operations on the target qubit, and the causal baseline is its
  connected component.

The RQ1-RQ3 soundness and size numbers are measurements of that simpler slicer.

**D2. Table VI and Fig. 2 are not reproducible.** Table VI was produced on June 29-30, 2026 by
running the four-edge implementation (`rq4_ablation/src/`) through a driver that was not saved. The
list of the 34 circuits and the per-circuit output were not saved either. None of them was found
in any local copy, archive or version-control repository of the project. An earlier complete run of
the same implementation on 69 circuits is included unchanged (`rq4_ablation/archived_69_circuits/`).
It gives the same ordering (ED > MD >= UED > CD) but different rates. In that run the full slicer has
a soundness-violation rate of 0.275, not 0. No driver was reconstructed, because a subset chosen to
match the table would not be a reproduction.

**D3. The Isabelle theory does not establish semantic preservation of the slicer.**
`SemanticPreservation_v2.thy` builds (exit 0, no `sorry`), but only relative to four axioms, two of
which are unsound as stated:
- `unitary_off_V_preserves_rdm` quantifies over a qubit `q` that does not occur in
  `apply_unitary rho U`, so it asserts that every unitary preserves every reduced state;
- `rdm_locality` is false for entangling gates.

In addition, `project V` keeps exactly the gates that touch V. That is the naive slice, not the
QPDG slice. The mechanization claim (Table VIII, Fig. 4) is therefore withdrawn.

**D4. RQ3 forward completeness of 1.0 is by construction.** `forward_coverage` in
`rq1_rq3_rq5/qdg.py` (lines 286-302) computes the QPDG forward set as the source's connected
component intersected with the `influence_truth` oracle, then scores it against that same oracle.
The QPDG row of Table V is therefore 1.0 by definition. The causal row is the whole connected
component, so it is 1.0 whenever influence stays inside the component. The naive row covers only the
source qubit. The measure is also computed over qubits, not the operations the paper describes, and
only the naive row (0.702) is an informative measurement.

**D5 (related, not one of the four points above). Oracles for RQ4 and RQ7.** Table I says every RQ
uses the exact fidelity oracle. The four-edge implementation (RQ4) instead judges soundness with
shot-based TVD against an empirical threshold, and RQ7 uses TVD on hardware counts (delta = 0.05).
The hardware slices were computed by the four-edge implementation's `QSLICE_FULL` variant, not by the
evaluation code of D1.

## Corrected experiments (`corrected_results/`)

These were written after review, to replace the evaluation parts that cannot stand:
- all choices were fixed in `corrected_results/PROTOCOL.md` and committed before any full run;
- one deviation was made, before any result existed, and is recorded in `DEVIATIONS.md`;
- each run was made once, and every result is reported;
- `corrected_results/regenerate.py` reruns them all and compares every output file byte for byte;
- the oracle is exact for dynamic circuits: pure-state branching over measurement, reset and
  `if_else`, judging the criterion's reduced-state fidelity >= 1 - 1e-6.

The rows below are the headline results against the submitted values. Full results and every
per-pair record are in `corrected_results/README.md` and `results/`.

| Claim | Submitted | Corrected |
|---|---|---|
| Table VI ΔSVR (ED / MD / UED / CD) | 0.588 / 0.382 / 0.294 / 0.000 (n = 34 circuits) | 0.535 / 0.129 / 0.128 / 0.043 (n = 962 pairs, 177 circuits); dynamic-circuit pairs: 0.399 / 0.481 / 0.217 / 0.159 |
| Full four-edge slicer SVR | 0 | 0.0052 (5 pairs, all in circuits with mid-circuit measurement) |
| QPDG invalid rate (RQ1) | 0.000 | 0.000 (Sec. III method, 784 pairs) |
| Naive def-use invalid rate (RQ1) | 0.429 | 0.276 |
| Slice size, QPDG vs causal (RQ2) | 0.433 vs 0.758 (43% smaller) | 0.540 vs 0.704 (23% smaller) |
| Forward completeness, QPDG vs naive (RQ3) | 1.000 vs 0.702 (QPDG by construction) | 1.000 vs 0.988 (both measured) |
| RQ5 scalability | build < 1 s on all 1,124 circuits (simplified implementation) | Sec. III implementation: 993 of 1,062 parsable circuits completed (69 reached 4 GiB); median build 28 ms, max 20.8 s; end-to-end pruned slicing median 43 ms, max 8.0 s, at most 214 MB |

What changes in the paper's claims:
- **Unchanged:**
  - the Sec. III method is sound on every pair;
  - it is more precise than the causal cone;
  - entanglement edges are the most necessary edge type overall.
- **Weaker:**
  - the precision gain is 23%, not 43%;
  - the naive baseline fails on 27.6% of slices, not 42.9%;
  - the RQ3 forward-completeness advantage is small (0.988 vs 1.000).
- **Wrong in the submission:**
  - CD edges matter: ΔSVR 0.043 overall and 0.159 on dynamic circuits, not 0;
  - MD and UED are tied overall, not ordered MD > UED;
  - on dynamic circuits MD matters more than ED;
  - the four-edge slicer is not sound on 5 pairs.

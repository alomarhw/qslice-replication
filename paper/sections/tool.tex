\section{A Static Slicer for Qiskit Programs}\label{sec:tool}

Developers write Qiskit programs, not circuits, and a slice helps them only as lines of their program. We
therefore built a tool that slices a Qiskit program statically, from its source, with the QDG
of Section~\ref{sec:dependence}. Fig.~\ref{fig:overview} shows its steps on the Bugs4Q program of
Section~\ref{sec:example}.

\paragraph*{Parsing}
The tool parses the program with srcML~\cite{collard2011lightweight, collard2013srcml}, which turns source
code into XML that keeps every character of the source and marks its syntax and the position of each
element. srcML marks up Python syntax and knows nothing of quantum programs, so the quantum layer is ours.
A table of \numToolGateTable{} Qiskit instruction methods records which arguments of each are qubits, bits
and angles. With it, a \texttt{call} element such as \texttt{circuit.cx(0,1)} becomes a gate whose name
gives its kind and whose arguments give its qubits, as stage~2 of Fig.~\ref{fig:overview} shows. The tool
takes the structure of the program and the position of every element from srcML, and reads the text of
each expression with Python's own parser.

\paragraph*{Static interpretation}
The tool walks the srcML tree and turns it into an operation trace, as the execution-order analysis of
Behler et al.\ does for OpenQASM, the assembly-like language of quantum circuits~\cite{behler2024supporting}.
It evaluates the program's expressions over an abstract domain of known values, registers, bits and
circuits. It unrolls loops and records the iteration of each operation, inlines functions, and follows
\texttt{if\_test} and \texttt{c\_if}, Qiskit's two constructs for gates conditioned on measured bits.
Each value carries the lines that computed it, so the tool knows
the classical lines, the statements that compute an operation's qubits, angles and conditions. The QDG
 does not need angle values, so angles drawn at run time stay symbolic. Where a value cannot be
resolved statically, the tool over-approximates. An unknown qubit index makes the operation act on every
qubit it may denote. An unknown condition runs every branch from the state before it, and a variable that
the branches leave with different values becomes unknown. A \texttt{return}, \texttt{break} or
\texttt{continue} in such a branch does not end the analysis, and the rest of the function is read as
may-operations. A loop over an unknown range repeats its body once more than the number of qubits and bits
the body touches, at most \numToolMaxCopies{} times, which covers every chain of dependences through the
loop, and a variable that changes between copies leaves the loop unknown. Because the QDG never removes a
qubit from the needed set, these over-approximations can only enlarge a slice, and the tool reports each of
them, including a loop whose copies reach the cap. The largest circuit a program builds is the one it
slices. When a circuit is passed to code the tool does not
model, such as a rewrite of its directed acyclic graph (DAG) representation, the tool reports it as not
traced.


\paragraph*{Slicing}
The tool runs the backward pass of Theorem~\ref{thm:sound} on the trace. It skips barriers, which do not
change the state, and terminal measurements, which come after the criterion. An operation that may act on
several qubits adds all of them to the needed set, and the bits its condition reads. A bit leaves the
needed set only when a measurement certainly writes it, which is sound because the measurement discards
the bit's earlier value. The pass returns the operations of the slice, their lines and iterations, and the
classical lines they depend on, in time linear in the length of the trace.

\paragraph*{Forward slices and profiles}
The same trace gives the forward slices and qubit slice profiles of Section~\ref{sec:dependence}. A forward
pass from the operations of a line marks every later operation that acts on a reached qubit or whose
condition reads a reached bit, and a bit stops being reached when a measurement the start cannot affect
certainly overwrites it, as in the backward pass. The pass returns the lines and the qubits and bits
reached. On every operation and qubit of our test programs, one of which overwrites a bit before a
condition reads it, the forward slices are dual to the backward ones. A profile combines one
backward and one forward pass with the srcML of the gate calls on the qubit. Over the
\numProfBugsQubits{}, \numProfTextQubits{} and \numProfLintqQubits{} qubits of the Bugs4Q programs, the
textbook and \numProfLintqSample{} sampled LintQ files, the two slices of a qubit differ in length for
\numProfBugsFwdNeBwd{}, \numProfTextFwdNeBwd{} and \numProfLintqFwdNeBwd{} of them, and
\numProfBugsInFunction{}, \numProfTextInFunction{} and \numProfLintqInFunction{} are acted on inside a
function under a parameter's name. In \numProfTextAliasGenuine{} textbook programs, checked by hand, a
qubit has a second name, a function parameter or a loop variable over a register.

\paragraph*{Validation}
On \numToolDevPrograms{} programs that we wrote and can run, of up to \numToolDevMaxOps{} operations,
including Shor's order finding, Grover search, phase estimation, an adder, the Quantum Approximate
Optimization Algorithm (QAOA) and a repetition code, the static trace equals the circuit Qiskit builds. The
slice of every qubit equals the circuit-level QDG slice that the study uses on \numToolDevSliceEqual{} of
them. The remaining program nests conditional blocks, which the circuit-level slicer reads only by their
outer condition. On \numToolNestedDraws{} random product inputs, the state simulator of
Section~\ref{sec:design} finds the circuit-level slice wrong \numToolNestedStudyWrong{} times and the
tool's slice never. On the Bugs4Q programs of our study, read without being run, the trace equals the
prepared circuit for \numToolTOneExact{} of \numToolTOneBugs{} bugs. The remaining bug rewrites its circuit
as a DAG, which the tool reports. The tool's line slices equal those of the study on all
\numToolTTwoUnits{} units whose lines the study maps, which include the \numLinesUnits{} units of
Section~\ref{sec:results}, so the line-level results there are those of the tool. No program crashes the
tool. A circuit comes from \numToolBugsCircuit{} of the \numToolBugsQiskit{} Qiskit programs of Bugs4Q,
\numToolBugsResolved{} of them without over-approximation, from \numToolTextbookCircuit{} of the
\numToolTextbookQiskit{} notebooks of the Qiskit textbook~\cite{qiskittextbook}, and from
\numToolLintqCircuit{} of the \numToolLintqQiskit{} GitHub programs collected for the LintQ
analyzer~\cite{paltenghi2024lintq}, where the 60~s limit stops \numToolLintqTimeouts{}. The others build no
circuit or are fragments. The median time per Bugs4Q program is \numToolBugsMedianMs{}~ms, srcML included.

\section{A Static Slicer for Qiskit Programs}\label{sec:tool}

Developers write Qiskit programs, not circuits, and a slice helps them only as lines of their program. We
therefore built a tool that slices a Qiskit program from its source, without running it, with the wire rule
of Section~\ref{sec:dependence}. Fig.~\ref{fig:overview} shows its steps on the program of
Section~\ref{sec:example}.

\paragraph*{Parsing}
The tool parses the program with srcML~\cite{collard2011lightweight, collard2013srcml}, which turns source
code into XML that keeps every character of the source and marks its syntax and the position of each
element. A gate call such as \texttt{circuit.cx(0,1)} becomes a \texttt{call} element whose name gives the
gate and whose arguments give its qubits, as stage~2 of Fig.~\ref{fig:overview} shows.

\paragraph*{Static interpretation}
The tool walks the srcML tree, as the execution-order analysis of Behler et al.\ does for
OpenQASM~\cite{behler2024supporting}, and turns it into an operation trace. It evaluates the program's
expressions over an abstract domain of known values, registers, bits and circuits. It unrolls loops and
records the iteration of each operation, inlines functions, and follows \texttt{if\_test} and
\texttt{c\_if} conditions, as Fig.~\ref{fig:loops} shows for the ansatz. Each value carries the lines that
computed it, so the tool knows the classical lines on which an operation's qubits, angles and conditions
depend. Angles drawn at run time stay symbolic, which the wire rule does not need. Where a value cannot be
resolved statically, the tool over-approximates. An unknown qubit index makes the operation act on every
qubit it may denote, an unknown condition runs every branch, and a loop over an unknown range runs its body
twice. Because the wire rule never kills a qubit, these over-approximations can only enlarge a slice, and
the tool reports each of them. A circuit handed to code the tool does not follow, such as a rewrite of its
DAG, is reported as not traced.

\begin{algorithm}[t]
\caption{Wire-rule slice of a static operation trace}\label{alg:slice}
\footnotesize
\begin{algorithmic}[1]
\Require trace $o_1 \dots o_m$, criterion $W$ (a set of qubits)
\State $N \gets W$; \ $S \gets \emptyset$ \Comment{needed locations, slice}
\For{$k \gets m$ \textbf{down to} $1$}
  \If{$o_k$ is a barrier or a terminal measurement} \textbf{continue} \EndIf
  \State $Q \gets$ every qubit $o_k$ may act on; $B \gets$ the bits $o_k$ measures into
  \If{$(Q \cup B) \cap N \neq \emptyset$}
    \State $S \gets S \cup \{k\}$
    \If{$o_k$ certainly writes bit $b$} $N \gets N \setminus \{b\}$ \EndIf
    \State $N \gets N \cup Q \cup \mathit{cond}(o_k)$ \Comment{reads all its qubits}
  \EndIf
\EndFor
\State \Return $S$, the lines and iterations of $S$, and their classical lines
\end{algorithmic}
\end{algorithm}

\paragraph*{Slicing}
Algorithm~\ref{alg:slice} is the backward pass of Theorem~\ref{thm:sound} on the trace. It returns the
operations of the slice, their lines and iterations, and the classical lines they depend on. Its cost is
linear in the length of the trace for a fixed criterion.

\paragraph*{Validation}
On \numToolDevPrograms{} programs we wrote and may run, of up to \numToolDevMaxOps{} operations, including
Shor's order finding, Grover search, phase estimation, an adder, QAOA and a repetition code, the static trace
equals the circuit Qiskit builds. The slice of every qubit equals the study's circuit-level wire slice on
\numToolDevSliceEqual{} of them. The remaining program nests conditional blocks, which the circuit-level
slicer reads only by their outer condition, and the oracle confirms that the tool's slice is the correct
one. On the Bugs4Q programs of RQ3, read without being run, the trace equals the prepared circuit for
\numToolTOneExact{} of \numToolTOneBugs{} bugs. The remaining bug rewrites its circuit as a DAG, which the
tool reports. Its line slices equal those of the study on all \numToolTTwoUnits{} units, so the line
results of RQ3 are those of the tool. On all \numToolBugsQiskit{} Qiskit programs of Bugs4Q, every program
parses, \numToolBugsCircuit{} yield a circuit, \numToolBugsResolved{} of them without any
over-approximation, and none crashes the tool. The others build no circuit or are fragments. On the
\numToolTextbookQiskit{} Qiskit notebooks of the Qiskit textbook~\cite{qiskittextbook},
\numToolTextbookCircuit{} yield a circuit. The tool takes \numToolBugsMedianMs{}~ms per program in the
median, srcML included.
